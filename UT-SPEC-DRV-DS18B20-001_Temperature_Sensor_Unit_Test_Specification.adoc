== Purpose

This document defines the unit-level test specification for the `drv_ds18b20` module of the OrgPort S32K312 firmware:

* *drv_ds18b20* — DS18B20 1-Wire digital temperature sensor driver (`common_libs/drivers/sensors/ds18b20`)

The purpose is to verify that the module's public API (`DRV_DS18B20_Init`, `DRV_DS18B20_Read`) behaves correctly under nominal, boundary, and fault-injection conditions prior to integration testing on the S32K312 node.

== Scope

This specification covers white-box and black-box unit tests for `drv_ds18b20`, exercised on the host build via the `common-libs/tests` Unity harness, together with the on-target hardware verification tests required to close the acceptance criterion in OP-SDP-001 (task T-J2-07). It does not cover:

* `lib_onewire` bus-protocol correctness (covered by its own unit test suite, `test_lib_onewire.c`)
* Integration behaviour between `drv_ds18b20` and the workflow engine, FEM, or CANopen TPDO packaging (covered by the Integration Test Specification)
* ROM search / multi-drop 1-Wire operation — the driver supports SKIP ROM (single device) only in this revision; ROM search is reserved for a future release
* System-level or clinical performance testing

=== General Preconditions (apply to all test cases unless overridden)

. For host-build test cases: `stub_gpio_reset()` and `stub_time_reset()` have been called immediately before the test case (performed automatically by the `ds_setup()` helper in `test_drv_ds18b20.c`).
. For on-target test cases: the DUT is freshly power-cycled or reset before each test suite execution, `Clock_Ip_Init()` has been called, and the 1-Wire GPIO pin direction/pull configuration matches the peripheral allocation in OP-SDP-001 §5.2.
. `DRV_DS18B20_Config_t.resolution` is `DRV_DS18B20_RES_12BIT` (0.0625°C, 750 ms conversion) unless a test case explicitly varies it.
. The driver under test does not call `LIB_FEM_Report()` — fault reporting is the caller's responsibility and is out of scope for this specification.
. Test results are recorded in the Test Execution Report (document TER-DRV-DS18B20-001).

=== Pass / Fail Criteria

A test case passes when *all* expected results stated for each step are met with no deviation. Any single deviation constitutes a failure and must be recorded with an incident report reference.

=== Automated Test Execution Procedure

The 13 automated test cases in this specification (see the *Execution* column of the Test Traceability Matrix) are all exercised by a single host-build Unity run. This procedure is performed once and the resulting console output is the evidence attached for every automated test case below.

. From `common-libs/tests/`, run `make` (equivalently `make build run`). This compiles `test_runner.c`, all `test_*.c` suites (including `test_drv_ds18b20.c`), `drv_ds18b20.c`, `lib_onewire.c`, `lib_crc.c`, and the stub sources, then executes `./test_runner`.
. Unity prints one line per test case in the form `test_drv_ds18b20.c:<line>:test_<name>:PASS` (or `FAIL` with the assertion detail).
. Confirm the summary line at the end of the run reads `13 Tests 0 Failures 0 Ignored` for the `drv_ds18b20` suite (the run also reports totals for the other suites registered in `test_runner.c`).
. Capture **one** console log of the full run.
. For each automated test case below, locate its test function name in the captured console log and confirm the line ends `PASS`.

== Module: drv_ds18b20 — DS18B20 Temperature Sensor Driver

=== Overview

`drv_ds18b20` provides temperature acquisition from a single DS18B20 1-Wire digital sensor. It layers on top of `lib_onewire` (bus reset/presence, byte and block read/write) and `lib_crc` (CRC-8/MAXIM validation), and exposes two functions:

* `DRV_DS18B20_Init(cfg)` — verifies device presence, writes the resolution to the scratchpad configuration register, and reads back the scratchpad to confirm the write via CRC.
* `DRV_DS18B20_Read(cfg, out)` — issues Convert T (0x44), blocks for the resolution-dependent conversion time using the caller-supplied `delay_ms`, reads the 9-byte scratchpad, validates CRC-8 over bytes 0–7 against byte 8, and converts the raw 16-bit two's-complement value to °C (12-bit resolution: 1 LSB = 0.0625°C).

All platform dependencies (`gpio_set`, `gpio_read`, `gpio_set_dir`, `delay_us`, `delay_ms`) are received as function pointers in `DRV_DS18B20_Config_t` at call time — the driver contains no RTD or STM32 HAL calls, per the layering rules in OP-SDP-001 §4.3.
